# 产品主流程文档

本文档描述当前项目已经实现的主流程，以及后续阶段的扩展路线。

## 1. 登录流程

1. 用户打开登录页
2. 选择登录或注册模式
3. 调用 `/api/auth/register` 或 `/api/auth/login`
4. 登录成功后保存 JWT 与用户信息到本地存储
5. 跳转到聊天页
6. 聊天页通过 `/api/auth/me` 恢复用户信息

失败分支：

- 认证失败：显示接口错误提示
- 网络失败：显示“请确认后端服务已启动”

## 2. 对话启动流程

1. 前端进入聊天页
2. 调用 `/api/conversations` 获取当前用户的对话列表
3. 前端根据本地项目分组映射筛选当前项目下的可见对话
4. 若列表为空，则自动为当前项目创建第一条对话
5. 若列表非空，则自动加载当前项目下第一条对话的消息历史
6. 前端建立 `/ws/{conversation_id}` 实时连接

说明：

- 当前项目分组由前端本地 `projectStore` 管理，并持久化到浏览器本地存储
- 当前项目页已支持搜索、创建、编辑、删除项目，并可在本地迁移对话归属
- 当前真实后端持久化实体仍为“用户、对话、消息”
- 尚未引入独立的后端项目实体，阶段二后再升级

## 3. 当前阶段一对话流程

1. 用户在聊天输入框中发送消息
2. 前端调用 `POST /api/conversations/{id}/chat`
3. 后端保存用户消息
4. 后端加载对话历史并启动 Manager Agent
5. 后端通过 WebSocket 推送 `log`
6. 后端推送 `agent_status=running`
7. Manager 通过统一 LLM 适配层获取真实流式输出
8. 后端持续推送 `token`
9. 完整回复持久化到数据库
10. 后端推送 `agent_status=done`
11. 对话 `updated_at` 刷新，历史列表排序更新
12. 前端保留当前对话与项目的映射关系，刷新后仍可在对应项目下找到历史记录
13. 用户可在聊天窗口顶部输入关键词，在当前对话历史中快速搜索并跳转到匹配消息
14. 用户可在设置页维护自定义角色模板，重新规划工作流后按触发关键词自动并入新的节点链路

当前实现说明：

- `LLM_PROVIDER=auto` 时，会优先使用已配置的云模型 Key
- 若未配置云模型 Key，则默认尝试本地 Ollama
- 当前阶段仍只做普通对话，不进入工作流规划

## 4. 错误恢复流程

1. 若 HTTP 请求失败，前端显示统一错误提示
2. 若 Token 失效，前端清空本地登录态并跳回登录页
3. 若 WebSocket 断开，前端最多自动重连 3 次
4. 若 3 次重连仍失败，前端保留消息并提示用户手动刷新或重新进入对话
5. 若当前项目下暂无对话，前端保持空状态，不强制跳转到其他项目的历史对话

## 5. 当前阶段二预览与执行流程

当前已经实现的阶段二最小链路如下：

1. 用户先通过普通聊天补充需求
2. 聊天页加载当前对话下已有的工作流预览记录
3. 用户点击“生成预览”
4. 后端读取当前对话历史
5. 需求提取器生成结构化需求摘要
6. 工作流规划器基于需求动态选择 PM / 前端 / 后端 / 测试 / 设计师模板并生成串行 DAG
7. 后端将预览持久化到 `workflows` 表
8. 前端展示工作流确认卡片、节点拆分和约束摘要
9. 用户可点击“重新规划”生成新的预览版本
10. 用户可点击“确认工作流”将预览状态更新为 `confirmed`
11. 用户可点击“开始执行”启动最小串行编排
12. 后端按节点依赖顺序依次调用执行 Agent
13. WebSocket 推送 `workflow_update` 和 `log`
14. 前端将 `orchestrator` 与 `node_*` 的 `log` 事件实时写入独立工作流日志面板
15. 后端在仓库根目录 `workspace/projects/...` 创建当前工作流共享工作区
16. 后端同时维护同一对话维度的 `project_memory.json`，沉淀长期目标、关键摘要与最近异常
17. 每个节点完成后将摘要写入对话历史、工作流执行日志、共享工作区交接记录和项目级记忆
18. 若当前节点命中断点配置，工作流进入 `waiting_confirm` 并保存运行快照
19. 用户可通过控制接口发送 `resume / redirect / abort`
20. 若节点执行失败，系统会按节点 `max_retries` 自动重试
21. 若超过最大重试次数，系统会回滚到最近安全快照，并生成上级角色、失败原因与恢复建议
22. 若节点模板包含 `file_tool`，Agent 会在共享工作区 `artifacts/` 下真实生成文本摘要产物
23. 若节点模板包含 `api_caller`，Agent 会在共享工作区 `artifacts/` 下真实生成接口响应产物
24. 若节点模板包含 `code_executor`，Agent 会在共享工作区 `artifacts/` 下真实生成业务产物
25. 若节点模板包含 `browser_tool`，Agent 会在共享工作区 `artifacts/` 下真实生成页面截图与访问元数据
26. 若节点模板包含 `image_tool`，Agent 会在共享工作区 `artifacts/` 下真实生成设计概念图与图像结果元数据
27. 前端在节点完成、失败、断点等待和终态时自动刷新当前对话的工作流与消息历史
28. 用户修正失败节点配置后，可通过 `resume` 或 `redirect` 重新执行当前失败节点
29. 工作流完成后状态更新为 `completed`，并在 `workspace.artifacts` 中返回最新产物列表
30. 前端读取 `/api/workflows/{conversation_id}/{workflow_id}/artifacts` 获取当前工作流产物列表
31. 用户在聊天页产物面板选择某个文件后，前端调用 `/artifacts/file` 读取真实文件内容
32. 前端根据产物类型切换代码、文档或图片预览组件，并保留当前工作流上下文
33. 用户可在产物面板触发导出，前端调用 `/artifacts/export` 下载当前工作流全部真实产物压缩包
34. 工作流进入运行、等待确认、完成或中断等关键状态时，后端通知器会记录本地通知日志并尝试发送桌面提醒

当前实现说明：

- 执行链路当前为最小串行版本，尚不支持并行节点
- 已接入 WebSocket 工作流事件，用于回显进度和节点状态
- 节点摘要与执行日志当前通过“事件驱动 + 接口回拉”方式补齐到前端
- 聊天日志与工作流运行日志已分区展示，避免普通对话日志被编排事件淹没
- 共享工作区当前已支持状态快照、交接记录和工作区路径回传，后续工具产出物会继续落到同一目录
- 当前阶段三已落地最小文件工具、接口调用工具与代码执行工具，能在共享工作区中真实生成摘要文件、接口响应文件、计划文件并回传产物路径
- 当前阶段三已落地最小浏览器工具，能在共享工作区中真实生成页面截图与访问结果元数据并回传产物路径
- 当前阶段三已落地最小图像工具，能在共享工作区中真实生成设计概念图、图像元数据，并在缺少图像模型 Key 时回退到本地占位图渲染
- 当前阶段三已落地受保护产物访问接口、聊天页产物预览面板与一键导出能力，可直接查看或下载真实截图、设计图、Markdown 摘要和 JSON 计划文件
- 当前阶段四已落地后端本地通知器，关键工作流状态会写入 `logs/notifications.log`，Windows 环境下会额外尝试气泡提醒与系统声音
- 当前阶段四已落地用户级自定义角色模板，启用后会在重新规划工作流时按关键词自动匹配，并以 `custom` 来源写入节点
- 项目级记忆当前已支持跨工作流沉淀长期目标、关键摘要和最近异常
- 断点控制当前已支持节点后暂停、等待确认、恢复执行与基础改向信号
- 错误恢复当前已支持自动重试、快照回滚、上级上报与失败节点重跑
- 每个执行节点当前通过绑定的角色模板和统一 LLM Agent 生成文本交接摘要
- 同一对话可保留多条预览记录，前端默认展示最新一条

## 6. 后续阶段二扩展流程

后续会在当前预览链路之上继续扩展：

1. DAG 编排器支持并行节点与并发上限
2. 基于当前模板链路继续扩展更丰富的角色职责、工具与权限边界
3. 继续补齐批量操作和更多文件类型预览
4. 持续增强断点、失败恢复和人工确认策略
5. 引入共享工作区和项目级记忆

## 7. 当前状态机建议

### 对话状态

- `idle`
- `connecting`
- `sending`
- `streaming`
- `completed`
- `error`

### 工作流状态

- `collecting_requirements`
- `ready_to_plan`
- `awaiting_confirmation`
- `running`
- `waiting_confirm`
- `paused`
- `failed`
- `completed`
